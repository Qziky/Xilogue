# 日常使用长测

更新：2026-10-26。已有用户自行启动的本地运行记录，尚未验收；用户目前无法验证，已要求先记录待完成并继续开发。以下保留为后续操作说明，不要求现在执行；结果仍统一维护在 [测试矩阵 W14](testing.md)。旧版本窗口需先暂停并退出，新代码重启后生效。

## 开始

1. 先退出之前打开的 昔录 · Xilogue 窗口，避免两个采集程序同时运行。
2. 在项目根目录的 PowerShell 执行：

   ```powershell
   uv run --locked python tests/manual/real_usage.py
   ```

3. 浏览器打开本地 Web UI，概览上方显示“日常使用长测”提示。点击“开始采集 / 恢复采集”，然后正常使用电脑。保持启动命令所在终端打开；不要用关闭网页代替退出程序。

每次启动创建独立的 `data/real-usage/<本轮编号>/`，不会覆盖原有正式数据。默认复用 `%LOCALAPPDATA%\Xilogue\config.json`，不存在时使用默认配置；有效配置副本保存在本轮 `app/config.json`。无须修改配置；本轮尽量保持参数不变，确需修改时记下时间和改动。可加 `--config config/config.example.json` 显式使用项目样例。只检查准备情况、不打开界面或创建数据的命令为 `uv run --locked python tests/manual/real_usage.py --check`。

## 正常使用

- 先进行一轮不少于 1 小时的日常使用；核对结果后，再另行启动一轮独立的 8 小时测试。时长从点击开始算起；窗口顶部时间包含启动后等待与暂停时间，分析时会另看状态记录。
- 照常浏览网页、阅读、编辑代码、滚动和切换应用即可。方便时做一次“暂停 → 等到已暂停 → 恢复”；记住明显卡顿、错误、疑似漏采的大致时间即可，不必持续盯着调试界面。
- 默认连续 90 秒没有鼠标键盘输入会暂缓采集，有输入后重新检查并恢复。这可能漏掉长时间阅读或视频变化；属于当前空闲策略，分析时单独记录。
- 涉及密码、支付、私人聊天或其他不希望保存的内容，先点暂停并等到“已暂停”，离开后再恢复。进程排除无法自动识别浏览器内所有敏感页面。截图和数据库均保存在本机，不上传、不提交 Git。
- 正常离开电脑可锁屏；如果电脑休眠、关机或重启，请记下大致时间。休眠产生的采样缺口不能充当连续运行证据，也不要为了凑时长改系统电源设置。锁屏/UAC 等专门验收仍按矩阵要求核对。

## 结束

1. 回到调试窗口，点击“暂停”，等状态变成“已暂停”。
2. 点击“退出程序”，等待终端输出 `Usage report saved: ...session.json` 并回到提示符。网页会显示退出提示；不要直接关闭终端或强制结束进程。
3. 回来告诉 Codex“测完了”，附大致使用时段及是否有卡顿、错误、休眠或疑似漏采；没有异常直接说没有即可。无需上传原始截图或数据库。

如果程序异常退出，也保留本轮目录并描述现象；缺少干净退出标记或末尾汇总会作为异常证据，不能当作正常完成。

## 数据与后续分析

| 本轮文件 | 用途 |
| --- | --- |
| `session.json` | 版本、依赖、配置、起止时间、退出与诊断完整性 |
| `metrics.jsonl` | 启动、每 60 秒及退出采样：CPU、内存、线程、句柄、累计 I/O、队列、计数、存储和最近保存帧耗时 |
| `events.jsonl` | 带 UTC 时间的开始、暂停、保存/跳过原因与错误代码，不含窗口标题、图片路径或内容 |
| `app/` | 本轮配置、SQLite 元数据和 WebP；元数据可能包含窗口标题，图片包含实际前台内容，仅供本机使用 |

指标与事件文件分别最多保留 3×8MiB，发生覆盖或写入/队列丢弃会反映在汇总中。默认图像配额为 512MiB、保留期 7 天，按有效配置执行；到期或超额会回收旧图，配额不包括数据库与诊断文件。不要在分析前删除本轮目录。需要清空时先退出，再仅删除本轮专用目录；普通文件删除不保证介质安全擦除。

分析首先读取指标、事件和汇总，核对运行/暂停/空闲时段、睡眠缺口、CPU、RSS/私有内存趋势、线程/句柄增长、队列丢弃、错误、图像/数据库/临时文件增长及退出回收。CPU 同时记录单核百分比口径与除以逻辑 CPU 数的整机口径；首个 CPU 样本仅作初始化参考。耗时按每次采样最近 512 个已保存帧汇总，不能把重叠窗口合并成全程分布，也不代表显示到保存的完整延迟。

日常使用可以发现稳定性与性能问题；没有人工标记的变化数和抽样核对，不能计算准确漏采率或冗余率。具体漏采和图像质量按用户提供的时间点再在本地核对。最终通过、失败及未验证项写回现有矩阵，不据一次长测直接放行 P0。
