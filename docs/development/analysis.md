# AI 提供商与证据校验

2026-10-27 用户要求 AI 支持 API 接入、自选提供商和自动获取模型列表。摘要和向量检索分别配置，各自只有一个“提供商”入口，Ollama、OpenAI、DeepSeek、硅基流动和自定义服务并列，不再先区分“接入方式”。默认仍为本机服务；不会自动切换云端。预设仅填地址，不保证该服务的每个模型都支持摘要或嵌入。

## 选择 API

1. 暂停后进入“采集设置”，在“AI 摘要提供商”或“向量检索提供商”的统一下拉框中选择服务。
2. 选择预设或填写 API 基址和 API Key，模型列表会自动读取，可选择、输入筛选或点“刷新模型列表”；尚未保存的地址和密钥也可读取目录。目录不可用时保留手动输入模型 ID，不会自动选择或替换已选模型。基址填到 API 根路径，如 `https://api.openai.com/v1`，不要包含 `/chat/completions`、`/embeddings`、密钥、查询参数或片段。远程地址要求 HTTPS；HTTP 仅支持 `127.0.0.1`、`::1`、`localhost`。
3. 核对显示的目标地址和发送字段，主动勾选相应发送许可，保存并应用。更换服务地址会清除页面中待保存的密钥、环境变量引用和发送许可；保存过的密钥按用途与完整基址分别管理。选择回本地后不再使用 API 凭据。
4. 保存后点击“测试摘要连接”或“测试向量连接”。测试只发送固定合成文字，不读取真实记录、不开始采集、不将结果写为用户摘要。该请求也可能由提供商计费。随后可明确生成摘要或建立索引；自动处理开关仍默认关闭。

摘要使用 `POST {base_url}/chat/completions`，向量使用 `POST {base_url}/embeddings`，Bearer 鉴权，由 Python 后端直接请求。未配置凭据的本机兼容服务也可使用。当前不支持只提供 Responses 或 Anthropic 原生协议的服务，需使用其 OpenAI 兼容入口。每日回顾消费已有摘要，本身不新增远程模型请求；OCR 仍为本地 CPU。

摘要输出可选 JSON 模式、严格 JSON Schema 或仅提示词约束；所有模式均在本机执行同样的字段、范围和精确引文校验。默认 `ai_max_tokens=2048`、`ai_token_parameter=max_tokens`；模型要求时选择 `max_completion_tokens`，输出上限可调整为 256–32768。推理模型的输出预算也可能消耗在推理内容上，截断结果会拒绝保存。推理请求超时沿用 `ai_timeout_seconds`（5–600 秒，可在配置文件修改）。不会自动运行目录中的模型或重试到另一家服务。

### 模型目录

目录通过受保护的本机 `POST /api/ai/models` 请求后端代读：兼容服务使用 `GET {base_url}/models`，Ollama 已有服务使用 `GET /api/tags`。Ollama 向量原配置 `embedding_port=0` 仍使用项目专用模型目录，直接枚举该目录的 manifest 名称，既不启动服务，也不加载权重；显式使用 11434/11435 时才读取对应已有服务。统一入口保留上述已有配置和模型释放方式，不迁移或修改用户模型。

打开设置或修改服务、地址、凭据后，停顿 400ms 自动获取；请求只包含目录所需的目标和鉴权信息，不含截图、OCR、标题或查询词。目录读取不需要授予记录发送许可；分析和向量推理仍要求独立许可。尚未保存的密钥仅在本次请求中使用，不落盘。更换提供商会立即移除旧列表、取消等待并忽略旧响应，目录失败不清空手填模型。

后端最多同时读取两个目录，网络超时取 `ai_timeout_seconds` 与 15 秒的较小值；响应最多 4 MiB、最多返回 2000 个可用格式的模型 ID，去重排序并注明截断，不跟随供应商返回的其他 URL。下拉框每次最多显示 100 项，可继续输入筛选。目录信息不保证模型具有当前用途所需的能力，需通过明确的合成连接测试核对。

## 发送内容、凭据与失败

- 摘要最多发送一段内 8 条来源的 ID、捕获时间、应用名、前 80 字标题和各前 600 字 OCR / 网页文字，另含固定任务指令及 JSON schema。不会上传原图、整库、文件路径或浏览器 URL 字段；上述文字本身仍可能含敏感信息。
- API 向量建索引发送来源文字各前 450 字，语义查询发送最多 400 字查询词；两者都受向量提供商的独立发送许可约束。向量和检索结果保存在本机。
- API Key 在自动读取目录或显式保存时传给受保护的本机后端；只有保存时才使用 Windows 当前用户 DPAPI 加密在数据目录的 `ai-credentials.json`，不写入普通配置、日志、页面存储或备份。读取设置只返回是否已配置。输入留空保留原密钥，勾选清除后保存才删除相应用途/地址的密钥；不会清除其他提供商。DPAPI 不能防止同一 Windows 用户权限下的其他程序或已解锁会话读取凭据。
- 也可显式填写 `ai_api_key_env` / `embedding_api_key_env` 指定环境变量名，已保存密钥优先；默认不读取任何环境变量。清除已保存密钥后仍可能使用明确指定的环境变量。更换地址后须重新指定。
- 备份不含密钥，两个 API 发送许可在备份配置中重置为 false，恢复后必须重新选择许可。原服务收到的文字受该服务的数据政策约束；本地删除无法撤回已发出的请求或删除提供商副本。
- 不使用系统代理、不跟随重定向，不在失败后改发其他服务。401/403、429、连接故障、响应过大、非法 JSON、工具输出、无依据引文与截断均返回固定错误码，不回传上游错误正文。原始采集和字面检索不依赖 API 可用。

摘要记录保留 API 基址与模型 ID，方便核对来源。API 向量按基址和模型 ID 区分，不能验证提供商同名模型背后的权重版本；提供商更新同名模型后应重建全部索引。切换服务或模型不会自动重写已有摘要；可以明确重新生成。

## 本地 Ollama 与任务生命周期

活动片段可以明确发起“生成缺失的摘要”或单段重新生成；要求停止/暂停，随后只运行分析，不采集窗口或执行 OCR。默认不启用自动 AI。配置 ai_enabled=true 后，采集期间每 2 秒发现稳定片段（默认 60 秒无新来源，且 OCR 没有待处理/运行/可重试任务），自动排队；不会下载模型。semantic_enabled 同样选择稳定片段生成向量。重复发现不重置失败次数，活动变化撤销旧结果并等待重新稳定。暂停/停止不触发自动发现。API 处理必须另有已保存的相应发送许可。

本地 Ollama Provider 固定访问 127.0.0.1:11434，不接受远程 URL、系统代理或重定向，不提供执行工具。默认 recorder-vision:balanced；先核对已安装模型和 completion 能力，拒绝云端标识和 remote_host/remote_model。Ollama 不可用时保留持久失败任务、退避和重试上限，不影响采集或文字检索。重新发起分析可重置失败任务。

每段最多使用最近 8 条已完成 OCR 来源，各截取 600 字符；模型只能引用这些有界输入的来源 ID 及指定原文片段。结构、长度、有限数值、来源 ID 和原文子串均校验，不通过不入库。摘要、主题、关键词、重要度、置信度和不确定项连同模型及时间保存；界面始终标为 AI 草稿。引文校验不能证明推论正确，模型置信度不是客观精度。

任务领取 token、Session revision、来源有效性和暂停提交屏障共同阻止旧结果写回；删除来源、拆分/合并或 OCR 更新立即清除/失效旧分析。启动恢复中断任务，取消不消耗失败次数，异常最多自动尝试 3 次。批次结束自动暂停；不等待尚未到期的退避。退出等待当前请求及清理；暂停不能立即中断已发送的原生模型请求，但旧结果不再提交。

稳定片段的重复发现先检查持久任务/结果，不反复读取已处理的全部来源。单个自动片段最多 4096 条来源，超过后另建片段。概览同时显示后台分析、显式向量查询及释放未确认的状态；退出屏障等待查询完成后再结束自有服务。

批次 Provider 记录开始前已驻留的模型，只卸载本次自行加载的模型；结束显式发送 keep_alive=0 并核对 /api/ps，保留原驻留模型。清理无法确认会显示 model_release_unconfirmed，不能把工作线程退出等同于显存已归还。默认模型缺失时请自行按环境文档安装/注册，应用不修改 Ollama 全局设置。

本机实测 Ollama 0.40.11，模型文件沿用既有 9B。首轮合成测试一段引用校验失败，已拒绝；将来源及原文选项纳入动态 JSON schema 后，两段通过（本地 data/ai-acceptance/20261026T163820_459df3a2/report.json）。任务结束模型列表为空，临时服务已停止；整机显存 2526 MiB 是其他进程的合计背景占用，不代表模型仍驻留。该小样本不是正式摘要质量或性能验收。

官方接口：[Chat](https://docs.ollama.com/api/chat)、[结构化输出](https://docs.ollama.com/capabilities/structured-outputs)。合成材料复现：`uv run --locked python tests/manual/ai_acceptance.py`；不采集用户桌面，失败时保留报告。旧实机/长测待办继续有效。

API 协议核对：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[OpenAI 结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)、[DeepSeek 接入](https://api-docs.deepseek.com/api/responses)、[硅基流动 Chat](https://docs.siliconflow.cn/docs/api/chat-completions-post)。真实付费账户连通性与各提供商具体模型兼容仍须用户填写自己的配置后验证。

目录协议：[OpenAI Models](https://developers.openai.com/api/reference/resources/models/methods/list)、[Ollama List models](https://docs.ollama.com/api/tags)。
