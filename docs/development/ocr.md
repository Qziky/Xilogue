# 本地 OCR 与文字检索

更新：2026-10-27。P1 已实现，自动化与合成材料推理结果见 [测试记录](testing.md)。真实 WGC 联动、日常使用与长期验证待完成；不表示 P0 或 P1 已完整放行。

## 界面操作

在项目根目录运行 `uv run --locked xilogue`，浏览器打开 [本地 Web UI](web-ui.md)。先退出旧版本窗口，同一数据目录只允许一个实例。每次启动默认停止，既不截图也不领取 OCR 任务；初始化和恢复可以创建空库、迁移及整理任务状态。

点击“开始采集 / 恢复采集”后，程序采集前台窗口，并由独立 Worker 识别已保存图片，包括同目录现有积压图片。OCR 不在捕获回调内运行。概览显示处理状态、任务计数及脱敏错误代码，识别失败不关闭采集。

无需截图也能处理积压：停止/暂停时点“仅识别已保存图片”，本轮只领取开始时已到重试时间的来源，不读取前台窗口，不启动 WGC。该明确操作不受自动 OCR 开关限制，仍检查桌面可用性；无可领取任务时自动暂停并释放 OCR 会话，未来退避任务需稍后再执行。空批次不加载模型。它不改配置，也不自动开始采集。

手动“暂停”同时阻止截图与 OCR 内容提交。无法立即打断的本地推理可能仍在计算，但完成后的旧结果会丢弃，任务恢复为待处理；返回后释放 ONNX 会话，页面显示加载/释放状态。再次明确开始采集或仅 OCR 批次时才重新加载；退出等待工作线程及 ONNX 会话释放。默认 90 秒输入空闲只暂缓新窗口采集，已保存图片的 OCR 可继续处理；需要停止两者时主动暂停。

“记忆检索”可在未开始或暂停时使用：关键词留空浏览所有可用原图，包括未完成或失败的 OCR；输入可见文字时支持中文一字/二字短词、英文及代码片段，仅匹配已识别文字。可选应用进程名、本地日期时间及 OCR 状态；页面将时间转换为含时区的 ISO 值，CLI 直接使用如 `2026-10-26T09:00:00+08:00` 的值。起始含边界、结束不含边界，结束必须晚于起始。查询按字面子串，不支持布尔运算或语义搜索。Web 每页 30 条，可前后翻页；CLI 默认最多 100 条。选择后在详情中查看原图、文字与坐标，并可单条重试或删除，操作及清理边界见 [Web UI 说明](web-ui.md)。界面预览最多 32000 字符、100 个区域，完整原文和全部区域保存在本地数据库。

## 不启动采集的命令

先退出使用同一数据目录的窗口。默认目录仍为 `%LOCALAPPDATA%\Xilogue`；可以加 `--data-dir` 指向一个明确的应用专用目录。处理测试轮次时应选择其 `app/` 子目录，不是包含报告的父目录。

```powershell
uv run --locked xilogue --ocr-status
uv run --locked xilogue --ocr-once
uv run --locked xilogue --ocr-once --retry-ocr
uv run --locked xilogue --search "数据库"
uv run --locked xilogue --search "capture_frame" --app code.exe --limit 30
uv run --locked xilogue --search "中文" --after "2026-10-26T09:00:00+08:00" --before "2026-10-27T00:00:00+08:00"
```

`--ocr-once` 是明确发起的本地积压处理，独立于 GUI 开始状态及 `ocr_enabled` 开关；只处理当前到达重试时间的任务，不等待退避到期。每项异常最多自动尝试 3 次，退避为 5/10/20 秒；`--retry-ocr` 重置失败任务后重新处理。输出仅含计数与时间，有失败则返回非零；搜索命令按用户请求输出文字片段和元数据，应只在本机使用。

## 配置、模型和数据

配置仍为 version=1，旧配置缺少新字段时补默认：`ocr_enabled=true`，`ocr_threads=2`（整数 1–8）。将 enabled 设为 false 只停止自动 OCR，图片仍可保存并建立待处理任务；修改后先暂停并重新加载配置。数据库 schema=2 的事务升级、任务状态与删除传播见 [数据契约](../technical/data-model.md)。

引擎为 [rapidocr-onnxruntime 1.4.4](https://pypi.org/project/rapidocr-onnxruntime/1.4.4/)，ONNX Runtime 版本由 uv.lock 锁定。选用该固定接口及 wheel 自带的模型，以便部署后不再下载模型。仅启用 CPU；三个会话分别限制 intra-op 线程数，合成验证均为 2。该值不是整个进程线程上限。未调用 Ollama、GPU、远程 OCR 或 AI 摘要。

## 验证与限制

复现安全推理短测：`uv run --locked python tests/manual/ocr_acceptance.py`。只生成中文、英文、代码图片并做本地 OCR，不打开窗口、不采集桌面；结果位于忽略的 `data/ocr-acceptance/`。使用 Windows 已有微软雅黑/Consolas 字体，未安装或修改系统字体。

追加 `--engine-pass` 验证正式 Worker 的仅 OCR 模式、自动暂停与三份 ONNX 会话释放。该选项禁用自动 OCR，使用拒绝前台查询和捕获的测试对象；仍只处理程序生成的图片。报告保留弱引用释放检查与线程退出结果，不能把它当作长期内存曲线或真实锁屏验收。

已知限制：合成清晰文字通过不代表真实小字、低对比度、多语言或复杂排版已验；OCR 会误识别或丢失代码符号，不能用作代码还原保证。一/二字查询会扫描规范化文本，大库性能待测。[FTS5 trigram](https://www.sqlite.org/fts5.html#the_trigram_tokenizer) 用于三字及以上的候选检索；本机 SQLite 3.53.1 支持该功能。持续资源、真实漏采/冗余、实际关机流程仍按原验收矩阵保留待完成。
