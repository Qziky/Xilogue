# 产品规格

状态：产品方向已确认；功能按阶段实现。版本：1.1，2026-10-26。

## 定位与问题

用户每天阅读文章、论坛、GitHub、代码和视频，会接触有价值的信息，却不愿为每条内容手动收藏或记笔记。系统应自动保存必要的活动证据，使用户之后能够找回，并在次日主动看到值得回顾的内容。

产品定位分为两部分：

- 数字记忆检索是底层能力：保存可搜索、可追溯的历史。
- 自动知识发现与每日回顾是主要体验：整理主题、提炼摘要，帮助用户重新接触有价值的信息。

记录到窗口或画面只能证明发生过观察，不足以证明用户完整阅读、理解或学会了其中内容。不得把推测写成事实。

## 产品原则

1. 被动记录，主动回顾，尽量减少手工整理。
2. 默认本地运行和保存；采集不依赖 OCR 或模型可用。
3. 先保存通过隐私检查的新证据，再进行语义去重和价值筛选；同时遵守容量与保留策略。
4. 任何派生结论均可回到原始证据；来源不足时明确说明。
5. 用户可以随时控制采集、排除应用、查看记录和删除数据。
6. 逐阶段验证，不以大而全的架构代替端到端可运行结果。

## 目标平台与版本边界

首要平台为 Windows 桌面，先完成桌面 MVP，再考虑浏览器扩展。首阶段仅采集当前活跃窗口，按 HWND 验证 WGC 路线。

“Windows 桌面 MVP”是跨阶段目标，不等同于 P0 已具备完整产品能力。正式支持的 Windows 构建版本要在实测后声明，不能直接用底层 API 的最低版本代替产品兼容范围。

| 阶段 | 面向用户的能力 |
| --- | --- |
| P0 | 能可控、可解释地采集当前活跃窗口的变化画面 |
| P1 | 能按可见文字检索 Observation 并打开原图 |
| P2 | 能查看连续活动片段及其来源 |
| P3 | 能获得有证据的本地 AI 活动摘要 |
| P4 | 能看到昨日值得回顾的内容并反馈 |
| P5 | 在关键词检索基础上改善模糊找回与跨日主题 |
| P6 | 用浏览器结构化数据补充桌面证据 |
| P7 | 完善安装、更新、长期运行和产品体验 |

具体任务、门槛和旧编号映射只在 [开发路线](roadmap.md) 维护。

## P0 必须具备

- 前台窗口识别、窗口切换稳定等待、可配置的采样节流。
- 按目标窗口捕获，能处理失效、关闭、尺寸变化和捕获异常。
- 用户主动开始、可见状态、暂停与退出；按进程名排除、锁屏及安全桌面处理。
- 低成本视觉变化检测，保留局部文字或代码变化候选，解释保存与跳过原因。
- 有界候选队列、过载计数、任务失效机制。
- SQLite 元数据和独立 WebP 图片；配置、容量、保留期限、删除与错误恢复。
- 轻量调试面板，显示目标、状态、时间、变化分数、队列、丢弃及错误。
- 自动化测试、真实 Windows 测试记录与性能基准。

P0 提供基本控制与调试即可，托盘不是技术验证的前提。临时采集参数和候选技术见 [决策记录](../technical/decisions.md)；验收以 [测试规格](../development/testing.md) 为准。

## P0 范围之外

OCR、Session 聚合、AI 摘要、每日回顾、语义检索、浏览器扩展、全屏或多屏采集、音频录制、语音转写、视频内容理解、云同步、复杂 Agent 和知识图谱。

多显示器环境下验证“仅捕获当前窗口”属于 P0 兼容测试，不等于实现同时采集多个显示器。

全屏、多屏、应用自适应策略、音频和 Agent 接口仅保留扩展可能；没有获得当前实施承诺。后续功能不应扩大 P0 依赖。

## 后续产品入口

- 昨日回顾：主题、摘要、推荐理由、来源与反馈。
- 历史搜索：日期、应用、关键词及后续自然语言查询。
- 时间轴：按时段查看 Session、Observation 和原始截图。
- 设置与隐私：采集开关、排除、保留、容量、删除和模型配置。

2026-10-26 用户要求提前迁移 Web UI，2026-10-27 授权继续完整路线。当前本机界面已提供上述跨阶段功能；开发结果不等于全部实机和长期验收通过。网页默认停止采集，“退出程序”需回收后端、模型和工作线程；关闭网页不能当作退出保证。

## 衡量结果

采集阶段关注漏采、冗余、资源成本和可靠性；检索阶段关注已知内容找回率；回顾阶段关注用户认为有用的比例。指标定义与基准记录见 [测试文档](../development/testing.md)。

固定间隔采样不保证捕获所有瞬时弹窗或短暂内容；视觉差异也不等于语义价值。产品说明必须保留这些边界。
