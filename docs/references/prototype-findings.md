# 旧原型经验与风险

整理：2026-10-26。旧 personal-memory-p0 实验源码、启动脚本、配置与测试已按用户要求删除；本页保留此前静态核对的有效结论，不要求恢复旧工程。

这是旧原型技术参考，不能当作正式代码或实机通过证明。正式 P0 的实现及当前验证状态见测试文档。

## 可借鉴的设计

- 默认停止、明确开始，仅按 HWND 选择活跃窗口。
- 回调内复制帧数据，通过有界队列隔离后续处理。
- generation 令牌使旧目标和旧任务失效，提交前复查状态。
- 与最后一次成功保存的图比较，保留累积的小变化。
- 灰度缩略图、全局/局部指标解释去重，WebP 图片与 SQLite 元数据分离。

这些设计已合入 [目标架构](../technical/architecture.md)，仍需正式实现和验证。

## 需要避免的缺口

| 历史发现 | 性质 | 正式实现需要解决 |
| --- | --- | --- |
| 图像尺寸、网格和阈值写死在算法中 | 源码确认 | 配置化并校验组合，参数集中维护 |
| 全局状态锁包住比较与磁盘写入 | 静态风险，未实机复现 | 慢 I/O 不长期阻塞监控或 UI；证明暂停提交屏障 |
| 每次停止新建 daemon 线程，退出未统一等待 | 静态风险 | 防止快速切换时线程累积，确认资源释放 |
| 只在保存新图后执行保留清理 | 源码确认 | 启动及运行维护，不依赖下一张新图 |
| 文件与数据库无统一中断恢复 | 静态风险 | 核对孤儿/缺失文件，补偿提交与清理失败 |
| 保存时间被当作捕获时间，图片路径为绝对路径 | 源码确认 | 时间语义分离、UTC 与受控相对路径 |
| 配置只有 JSON 解析与直接取键 | 源码确认 | schema、范围、组合、错误提示和版本迁移 |
| 标题变化重建会话和比较基线 | 源码确认 | 窗口身份与可变标题分离，避免首帧冗余 |
| 只检查最小尺寸，无黑帧质量诊断 | 源码确认 | 不能声称异常黑帧已经过滤，实际色块与失败验证 |
| 队列满只有文本提示，无累计状态 | 源码确认 | 队列长度、丢弃计数和拒绝原因可观测 |
| 保存后立刻清理可能删掉刚保存的超额图片 | 静态风险 | 单图超额明确拒绝，不返回不存在的成功路径 |
| 只有五个图像用例和一个存储用例 | 覆盖缺口 | 暂停、并发、排除、异常、恢复、清理与实机补齐 |

旧代码已有 token 检查和异步停止，不能据上述风险断言它“完全没有隐私门”或“必然死锁/漏写”。正式验证以 [测试矩阵](../development/testing.md) 为准。

## 历史结论的处理

- 旧材料“6 passed”未经本地复现。此前在 Python 3.14 下重跑因缺 cv2 停于收集阶段，未验证算法断言，更未验证 WGC。
- windows-capture 2.0.1 发布接口已查到 HWND、独立线程启动和四通道视图；颜色顺序、缓冲有效期及原生停止行为仍需实测，出处见 [参考资料](README.md)。
- “5 秒”是采样节流，不能保证每 5 秒落盘或不漏瞬时内容。
- 旧 90 秒无输入直接暂停可能漏掉阅读/视频，正式策略需可配置并如实提示。
- 旧 512 MB 实际按 1024² 计算，且只统计登记图片，统一称 512 MiB 图像配额。
- 旧数据曾在 %LOCALAPPDATA%\PersonalMemoryP0，清理本仓库源码没有触碰这一外部目录；正式程序不得自动导入或删除历史数据。
- API 最低 Windows 版本不等于包或产品兼容范围；文件替换不等于跨 SQLite 的完整原子事务；普通删除不等于介质安全擦除。
